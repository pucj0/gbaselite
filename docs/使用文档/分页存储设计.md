# 分页持久化与冷数据查询

> 历史设计文档：snapshot/paged 运行入口已移除，以下配置和事务功能仅描述旧版本。新版本使用 MVCC；旧数据转换见[迁移步骤](../../README.md#旧数据迁移)。

这是可选的新存储后端，不代表完整 MySQL/InnoDB，也不代表所有 SQL 都能在固定物理内存内运行。默认 `snapshot` 后端继续兼容旧安装；正式数据目录没有被本次开发转换。

## 开启与迁移

```yaml
storage:
  mode: paged
  page_cache_mb: 4
  cold_reads: true
  cold_materialize_mb: 64
```

实际配置字段为 `storage.cold_reads`。`page_cache_mb` 限制保留的编码行页缓存；0 关闭此缓存。`cold_materialize_mb` 是复杂查询、事务和写入需要加载冷表时的估算准入上限。它不等于操作系统 RSS 上限，也不限制已经驻留的热表内存。

Go 接口：

```go
engine, err := executor.OpenWithOptions(directory, user, password, executor.OpenOptions{
    StorageMode: "paged",
    PageCacheBytes: 4 << 20,
    ColdRead: true,
    ColdMaterializeBytes: 64 << 20,
})
```

`NewPagedPersistence(...).Load()` 仍全量载入行和内存索引；`LoadCold()` 只加载元数据及不可变页引用。冷模式首次遇到旧 `store.gob` 时，仍需使用原有完整加载器读取旧格式；之后保存才生成分页文件。迁移阶段需要能装下旧库的内存，迁移后重新打开冷模式才会按页读取。

旧 `store.gob` 原地保留。发现 `store.pages`、`store.checkpoint` 或 `store.wal` 后，`snapshot` 模式会拒绝加载和覆盖该目录，避免配置切回去时悄悄读到迁移前旧数据。回退应先导出，再恢复到新的数据目录。

## 实际文件与提交顺序

`databases/` 下新增：

- `pages/<两位哈希前缀>/<SHA-256>.page`：不可变行页。
- `disk-indexes/<SHA-256>.idx`：不可变磁盘索引，包含叶页与多级范围边界页。
- `store.pages`：当前已提交的元数据和页引用清单。
- `store.wal`：写前日志，记录 PREPARE 和 COMMIT。
- `store.checkpoint`：检查点清单。

行页通常按估算内存 64 KiB 分块，每个物理 256 行块独立分割，单页最多 256 行。单个页/清单记录上限 64 MiB。每个行页含 CRC32C 头部和负载校验，文件名还校验 SHA-256；完整记录坏校验会报错，不能当空表继续运行。

一次保存按以下顺序执行：

1. 写入新行页和需要更新的磁盘索引，并同步文件；未变化的内容复用旧文件。
2. 追加含新清单的 WAL PREPARE 并同步。
3. 原子替换 `store.pages`；这是提交点。
4. 追加对应 WAL COMMIT 并同步。

清单替换之前失败，不会重放孤立 PREPARE。清单已经发布、COMMIT 尚未追加时进程终止，重开可从有效清单恢复新状态。清单缺失时，只可重放匹配完整 PREPARE/COMMIT 的提交；完整损坏记录直接拒绝恢复。最后一个不完整 WAL 帧可以作为中断的追加忽略，之后追加前只截断这个经过校验的尾部。

提交点之后出现错误意味着提交结果可能已经持久化，沿用执行器的失败后停止服务机制；不得在不检查结果的情况下自动重试业务写入。测试覆盖进程在清单发布前/后直接退出的恢复边界；这些测试不等于所有文件系统、控制器及断电场景的证明。

每 64 次提交或 WAL 达到 16 MiB 自动检查点。检查点和当前清单同步后才原子清空 WAL，然后回收未引用页与索引文件。活跃页迭代器或冷表快照会阻止旧文件回收；冷表共享快照的回收 pin 随其最后一个引用被 GC 后释放，因此旧文件可能延迟回收。

## 冷查询已接通的路径

冷表不保留全量 `Value` 行，也不重建内存唯一键映射和排序位置数组。行页按需解码，磁盘索引将主键/唯一键点查和范围扫描定位到所需行位置，随后读取对应行页。索引遍历只保留路径页，不为每个索引额外配置常驻缓存，避免索引数量放大缓存预算。

SQL 冷路径覆盖：

- 单表 `SELECT`、列投影和普通标量表达式、`WHERE`、`LIMIT/OFFSET`。
- `COUNT(*)` 及带过滤条件的计数。
- 优化器可以安全利用的主键/唯一键/复合索引条件及范围扫描。
- 索引能够满足的 `ORDER BY`，包括倒序和分页。
- 开启查询排序预算后，其他支持的单表 `ORDER BY` 使用外部排序；`DISTINCT` 使用同一查询临时磁盘预算，不先加载整张冷表。

列/会话排序规则或类型转换不满足现有优化器的保守条件时，可能走行页扫描，而非磁盘索引范围缩小；残余 WHERE 条件仍会复核。复杂 JOIN、子查询、窗口函数、GROUP BY/其他聚合及一般写入/DDL/BEGIN 目前会要求物化。超过 `cold_materialize_mb` 时明确报资源错误，不把未加载的数据当成空表。成功物化后的表继续按热表运行，不会自动重新变冷；重新打开冷模式可恢复按页读取。

仅开启 `paged` 而未开启 `cold_reads`，主要收益是减少持久化写盘量，不能降低全表行与内存索引驻留。

SHOW 基表元数据、系统变量及连接设置不会触发全库物化；SHOW 视图列定义可能执行视图，因此受物化预算约束。元数据 WHERE 中含子查询也必须经过预算检查。

## 磁盘索引的边界

磁盘索引使用有预算的外部排序构建，默认构建缓冲预算 8 MiB、合并扇入最多 16。支持复合键、唯一键 NULL 规则、DECIMAL 键及当前实现的列排序规则。单个索引键最多 64 KiB、最多 256 列；超限返回错误。

每次保存会对索引输入计算指纹。非索引列更新可继续复用已有索引文件；键或行位置变化时，重建受影响的完整索引文件。它还不是原地修改叶页、拆分页的增量 B-tree 写入实现。大量索引键更新、删除导致的行位置变化，仍有显著 CPU 与写盘成本。

行页持久化也仍需遍历和编码热表，才能判断哪些页变化；删除可能改变后续页的行分组。WAL 保存的是清单而非逐行修改指令。它减少重复写全库数据，但没有消除所有 O(N) 工作。

## 备份与检查

不能只复制 `store.pages`。完整目录备份必须包含所有相关 `databases/` 文件，并在停止写入后复制，避免检查点与回收期间混入不一致文件。

`Persistence.ExportSnapshot(path)` 可以把当前已提交 root 导出成完整、可独立读取的 gob，使用原子替换，目标必须在活跃分页数据库目录之外。导出持有该 Persistence 的提交锁，且目前会物化所有行，属于可能占用大量内存的管理操作。`InspectSnapshot` 面向完整 gob；直接检查保留下来的旧 `store.gob` 只能说明旧快照可读，不能说明分页实例当前健康。

完整 gob 格式版本现为 4，用于保留精确 DECIMAL 和列排序规则。历史版本仍通过迁移注册表读取；旧程序不应打开新版文件。

## 已执行验证

- 行更新复用未变化页，非索引列更新不重建磁盘索引。
- legacy 导入不修改原文件、完整 gob 导出再读、禁止配置降级读取旧数据。
- WAL PREPARE 不重放、缺清单从 COMMIT 恢复、不完整尾部恢复、完整 CRC 错误拒绝。
- 子进程在清单发布前和发布后退出，再启动验证对应旧/新行数。
- 冷扫描数据大于页缓存，完成后表仍无驻留行；主键点查只读取一个匹配行页。
- 倒序范围、复合键、DECIMAL 大整数键、唯一键与 NULL、损坏索引页错误传播。
- 物化预算拒绝、事务回退、SHOW 视图及子查询预算保护、冷外部排序/DISTINCT、临时文件清理。

这些结果证明已实现路径的正确性；尚未证明任意超内存写入、长期高并发或亿级数据规模能力。

低层 Go 调用补充：`LoadCold()` 的返回表需要使用能返回 I/O 错误的 `Visit`、`Stream`、`StreamIndex`、`CheckedCount`、`LookupUniqueChecked`，或先显式 `Materialize`。历史 `Select`、带谓词的 `Count`、`Project`、`LookupUnique` 等无错误返回接口不是冷读取 API；SQL 分流会在进入这些旧路径前完成预算检查。内存快照保留内部冷页引用用于事务/Store 交接，便携文件导出必须使用 `Persistence.ExportSnapshot`，不能自行把冷表的空驻留行切片当作完整数据序列化。

低层Go接口跨后端保存时，`NewPersistence(otherDirectory).Save(coldStore)` 会拒绝未物化
的冷引用，并保留目标旧文件；应先显式Materialize并检查预算，或使用分页Persistence的
ExportSnapshot。此保护防止gob忽略内部页引用后生成缺少行数据的快照。
