# 事务与存储说明 (GBaseLite B03)

本文档系统说明 GBaseLite MVCC 存储引擎的多版本并发控制、四级事务隔离系统、锁管理器、保存点管理及高可用复制一致性契约。

---

## 1. MVCC 存储架构与多版本可见性

GBaseLite 采用基于 bbolt 的 append-only 多版本快照存储架构（`mvcc.Store`）：

- **版本与时间戳**：每个已提交写操作被赋予全局严格单调递增的提交时间戳（CommitTS）。数据行包含创建版本号与删除版本号（Tombstone）；
- **快照读视图（Read View & ViewToken）**：
  - 视图分配由中立的隔离引擎接口 `storageengine.IsolationEngine` 管理；
  - 视图令牌（`ViewToken`）记录事务或语句的 `readTS`，并向低水位收集器注册 Pin 引用；
  - **版本回收防护（GC Pin）**：后台 `CompactHistory` 执行历史物理垃圾回收时，严格受系统当前存活的最小 `readTS` 阻断，任何处于活跃视图引用的历史快照绝不被提前回收；
- **存储代次栅栏（Store Generation Fence）**：
  - 当通过备份恢复（Restore）重置数据库状态时，Store Generation 计数器严格递增；
  - 跨代次的旧视图令牌与旧持锁所有者立即失效，防止旧代次悬挂读写污染新代次。

## 2. 四种事务隔离级别契约与实现机制

GBaseLite 支持 MySQL 8.4 规范定义的全部四种标准事务隔离级别：

### 2.1 REPEATABLE READ (可重复读，默认级别)
- **机制**：事务在执行**首个一致性普通读（SELECT）**时惰性建立事务级 Read View，并在后续整个事务生命周期内复用该快照视图；
- **自身写覆盖**：当前事务自身未提交的暂存写操作（Staged Writes）对本事务后续读操作优先可见；
- **当前读与锁定读隔离**：显式执行 `SELECT ... FOR UPDATE`、`SELECT ... FOR SHARE` 时，严格转为当前读（Current Read）并申请行锁，不建立也不刷新普通一致性快照；
- **防不可重复读与范围幻读**：并发事务提交的行修改或新增行对普通 SELECT 完全不可见。

### 2.2 READ COMMITTED (读已提交)
- **机制**：每个独立执行的 SQL 语句均动态分配一个独立的全新语句级 Read View（Statement View）；
- **可见性**：后执行的语句能够立即观察到其他事务最新提交的行变更；单条复合语句内部（如带聚合、子查询或 JOIN 的长计算）共享同一个原子快照，保证单语句时点一致性；
- **当前写保护与更新冲突**：在行锁保护下执行 `UPDATE` 时，以最新已提交数据为基线进行变更；若在加锁前被并发事务修改并提交，则基于最新提交版本更新，不产生虚假的陈旧版本冲突。

### 2.3 SERIALIZABLE (可串行化)
- **机制**：长事务中的普通 SELECT 语句隐式提升为锁定读（等效于 `FOR SHARE`），自动申请表级意向共享锁（IS）以及记录级共享锁（S Lock）；
- **范围与缺席点保护**：对于点查不存在的记录申请 Gap 锁，对于范围扫描申请 Next-Key 锁，防止并发事务插入导致幻读与 Write Skew；
- **自动提交只读优化**：单语句且 `autocommit=1` 的独立只读 SELECT 执行快速路径，不获取阻塞写操作的共享行锁；
- **Fail-Closed 复杂形态保护 (M27)**：对于当前无法精准施加范围谓词锁的复杂查询（如多表 JOIN、CTE、派生表、视图、集合 UNION、聚合），GBaseLite 严格采取 Fail-Closed 策略，直接返回 Error 3108（`this statement shape does not support row locking yet`），拒绝隐式降级执行。

### 2.4 READ UNCOMMITTED (读未提交，单机模式)
- **机制**：通过内存态脏数据发布注册表（`DirtyRegistry`）实现未提交版本的受控可见性；
- **原子发布与生命周期**：仅在写事务完成单条语句写入并校验约束后，才将阶段性脏版本挂载至全局注册表；事务回滚或断开连接时，脏版本被原子撤销清理；
- **可见性优先级**：当前事务自身写 > 外部并发事务未提交脏版本 > 全局已提交基线；
- **严禁脏写与丢失更新**：写操作（INSERT/UPDATE/DELETE）**严格强制申请互斥排他锁（X Lock）并校验已提交基线**，任何并发写事务尝试修改同一行均被排他锁阻塞，绝不允许发生脏写（Dirty Write）。

## 3. 作用域状态机与保存点

### 3.1 作用域状态机
- `SET [SESSION] TRANSACTION ISOLATION LEVEL <level>`：修改当前会话默认隔离级别；若当前存在活跃事务，当前事务不受影响，自下一事务起生效；
- `SET TRANSACTION ISOLATION LEVEL <level>`：仅修改紧随其后的**下一个事务（pendingNext）**的隔离级别；经一次隐式自动提交语句或显式 `BEGIN` 消费后，自动回退至会话默认级别；活跃事务中执行此命令将直接报错拒绝；
- **SET GLOBAL 拒绝 (M06)**：GBaseLite **不支持** `SET GLOBAL TRANSACTION ISOLATION LEVEL`。为杜绝单连接意外修改全局配置影响同进程内其他独立业务会话，明确拒绝全局作用域突变。

### 3.2 嵌套保存点（SAVEPOINT）
- 支持 `SAVEPOINT <name>`、`ROLLBACK TO [SAVEPOINT] <name>` 与 `RELEASE SAVEPOINT <name>`；
- 每个事务最多支持 32 层活跃保存点；
- 回滚至指定保存点时，保存点之后产生的写操作被完整撤销，脏版本注册表中对应的未提交版本被原子剔除；
- 在 READ COMMITTED 级别下，保存点的创建与回滚不冻结语句快照，回滚后的新语句仍可观察到外部最新已提交变更。

## 4. 锁管理器（Lock Manager）与死锁处理

GBaseLite 内置严格的行级锁管理器，提供细粒度的并发控制与死锁消解机制：

1. **锁模式与层次**：
   - 表级意向锁：意向共享（IS）、意向排他（IX）；
   - 记录级锁：共享锁（S）、排他锁（X）；
   - 谓词范围锁：间隙锁（Gap Lock）、临键锁（Next-Key Lock）、插入意向锁（Insert Intention Lock）；
2. **锁等待与超时**：
   - 冲突锁申请进入等待队列，受到 `innodb_lock_wait_timeout`（秒级）硬超时约束，超时返回 MySQL 1205 错误并仅终止当前语句；
3. **死锁检测（Deadlock Cycle Detection）**：
   - 当发生闭环死锁循环（例如 A 等待 B 且 B 等待 A）时，后台等待图周期分析器毫秒级检测出环路；
   - 自动选择较晚注册的等待事务作为受害者（Victim）回滚，向客户端抛出 MySQL 1213（`Deadlock found when trying to get lock; retry transaction`），幸存事务顺利完成。

## 5. Raft 高可用集群模式下的隔离级别限制

在启用三节点 Raft 复制集群时：

- **禁止 READ UNCOMMITTED (M36)**：显式执行 `SET SESSION TRANSACTION ISOLATION LEVEL READ UNCOMMITTED` 将返回 `storageengine.ErrUnsupported`（Error 1064）。因为未经过 Raft Quorum 共识的脏数据无法在线性一致性状态机间同步，为避免副本状态分叉，集群模式严格禁止 RU；
- **任期与领导权栅栏（Term / Tenure Fence）**：Leader 发生网络分区或下台事件时，本地代次锁重置机制自动注销所有等待队列，新 Leader 通过线性一致性 Barrier 恢复集群服务。

## 6. 兼容性边界与已知差异披露

GBaseLite 致力于为轻量级和嵌入式应用提供极高可靠性的 ACID 事务系统，**不承诺也不等同于完整的 MySQL 8.4 商业版**：

| 场景 / 特性 | GBaseLite 表现 | MySQL 8.4 表现 | 分类与说明 |
|---|---|---|---|
| `SET GLOBAL TRANSACTION ISOLATION LEVEL` | 报错 Error 1064 拒绝执行 | 允许并修改全局系统变量 | **KNOWN DIFFERENCE (M06)**：保护嵌入式多连接环境 |
| `SERIALIZABLE` 多表 JOIN / CTE / 聚合 | 报错 Error 3108 Fail-Closed | 加锁执行 | **UNSUPPORTED (M27)**：防谓词锁遗漏，消除幻读风险 |
| Raft 复制集群下执行 `READ UNCOMMITTED` | 报错 ErrUnsupported 拒绝 | (不适用，原生主从复制) | **UNSUPPORTED (M36)**：防止跨副本脏读发散 |
| MySQL 5.7 遗留别名 `@@tx_isolation` | 兼容支持并返回当前隔离级别 | 8.0+ 已移除报错 1193 | **EXTENDED COMPATIBILITY (M44)**：向后兼容旧驱动 |
| `READ ONLY` / `READ WRITE` 事务特征 | 暂不支持该语法特征 | 支持 | **NOT SUPPORTED** |
| `LOCK TABLES` / `UNLOCK TABLES` | 仅接受兼容语法，不提供全库表锁 | 提供完整表级锁定 | **COMPATIBILITY STUB** |
