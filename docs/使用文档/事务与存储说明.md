# 事务与存储说明

> 历史设计文档：snapshot/paged 运行入口已移除，以下配置和事务功能仅描述旧版本。新版本使用 MVCC；旧数据转换见[迁移步骤](../../README.md#旧数据迁移)。

本页说明 snapshot/paged 后端的保存点与事务快照。**MVCC 后端不支持保存点**，其快照隔离和写入路径见[MVCC 与复制](MVCC复制与高可用.md)。

## 保存点

- 支持 SAVEPOINT、ROLLBACK [WORK] TO [SAVEPOINT]、RELEASE SAVEPOINT；名称大小写
  不敏感、最多 64 字符，每个事务最多 32 个，同名替换并移动到最后。
- 回滚保留目标并移除之后的点，RELEASE 只移除指定点。事务外 SAVEPOINT 不保留；
  缺失点返回 1305，数量上限返回 1041。提交、完整回滚、断连释放全部引用。
- 保存点复制元数据和行头，共享不可变行载荷，不创建共享可写索引、不触发 fsync。
  因此不是常数空间操作，回滚仍重建索引；长事务与大量保存点仍会增加内存及阻塞。
- 普通 DML、外键级联、增量建表/视图/索引和增加列可恢复；没有实现 MySQL DDL 隐式
  提交。活动保存点下拒绝 DROP DATABASE/TABLE、TRUNCATE、表重命名、列的
  DROP/MODIFY/CHANGE/RENAME，包括含这些操作的批量 ALTER。先释放全部保存点再执行。
  此边界避免缺少稳定对象身份时错误复用自增预留值。
- 账号/授权、USE、会话变量和 LAST_INSERT_ID 不受保存点回滚影响。用户 CREATE
  TEMPORARY TABLE 尚不支持；内部查询临时表不进入持久化保存点。
- 已回滚 SQL 从待提交 binlog 中移除，自增预留值通过独立控制记录恢复，保留 ID 空档。
  普通记录继续写版本 1，含计数控制的记录写版本 2；新程序读 1/2，旧程序拒绝 2。
  数据库 gob 格式不变。关闭 binlog 时不保留无用途的事务 SQL。

## 事务快照

Store.Clone 直接复制已经校验的唯一键映射及有序位置数组，省掉重新计算键和排序。
行载荷沿用不可变共享约定，所有可写集合独立；不直接转移 Store 所有权。提交保持原有
ReplaceShared、同步持久化和失败处理流程，不能把克隆加速等同于持久化提交同比提速。

具体 SQL 用法见[SQL 使用教程](SQL使用教程.md)，性能实测统一见[四数据库对比报告](../报告/四数据库对比报告.md)。
