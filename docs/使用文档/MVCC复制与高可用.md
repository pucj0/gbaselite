# MVCC、低内存写入与三节点复制

MVCC 是唯一运行事务引擎，默认打开即使用 MVCC；snapshot/paged 仅用于离线旧数据迁移。
当前 SQL 范围见下表与 [README](../../README.md#兼容范围与限制)。它不是完整 MySQL，也没有长期生产故障认证。
迁移使用 `migrate-legacy --source <旧目录> --target <新目录>`，源目录保留。

## 已实现的路径

- bbolt 磁盘 B+树保存行版本、主键和唯一键；BEGIN 仅记录提交序号，不复制表数据。
- 每个事务/语句层使用约128 KiB编码缓冲，超过后批量暂存磁盘；只读事务不创建临时
  文件，语句失败不合并到事务。完整命令不超过64 KiB的小型单机事务一次原子同步
  提交；单机大事务直接从临时写集按约256 KiB分批同步写入不可见版本，省去持久pending；
  Raft保留可重放的持久暂存。最后一个原子提交标记才使全部行可见。
  缓冲预算含估算元数据，Go实际分配额外占用内存；持久库仍同步提交。
- 快照隔离：不同行的并发更新可都提交；同一行、唯一键或依赖的表结构发生并发变化，
  提交返回 1213，应重试整个事务。不是串行化隔离，没有间隙锁或 SELECT FOR UPDATE。
- 普通 INSERT VALUES、单表 UPDATE/DELETE 不物化全表。主键等值的查询、更新、删除
  可点查；已有单列/复合唯一索引支持安全整数全键等值定位，再回表验证 WHERE。
  新整数主键表可做安全范围访问，其它谓词逐页扫描。自增号批量持久预留，
  允许回滚及混合显式编号造成空洞。
- HashiCorp Raft 固定三投票节点复制实际写集，包括表结构、行、唯一键和自增号。
  多数派提交后才确认成功；选举后继续服务；少数派拒绝需要多数派的操作；重启可追赶。
- 行版本与 Raft 快照均从磁盘流式输出。恢复快照使旧本地事务失效；事务提交携带
  Raft 任期，不能跨选主后继续提交旧事务。节点 ID 和固定成员配置会持久校验。
- `gbaselite proxy` 自动探测可用主节点。切换时关闭旧连接；新连接进入新主。
  代理不重放 SQL、不恢复会话变量，不保证正在执行的事务透明续跑。

## 当前 SQL 范围

| 支持 | 限制 |
| --- | --- |
| CREATE/DROP DATABASE、USE、CREATE/DROP TABLE、TRUNCATE | DDL 属于本后端事务，没有 MySQL 隐式提交语义；SHOW 读取已提交元数据 |
| PRIMARY KEY、UNIQUE，建表时声明普通索引 | 主键和唯一键参与增量写入/冲突检测；新建单列INT/BIGINT主键表支持有序范围，旧表格式与普通索引仍无范围优化 |
| INSERT VALUES、表达式、预处理参数、JSON_OBJECT 等现有标量函数 | 不支持 INSERT SELECT/SET/IGNORE、REPLACE、ON DUPLICATE KEY |
| 单表 UPDATE/DELETE、WHERE、LIMIT | 不支持 JOIN 写入；LIMIT 没有排序承诺；ON UPDATE 列表达式拒绝建表 |
| 单表投影、WHERE、ORDER BY、DISTINCT、COUNT/SUM/AVG/MIN/MAX | 已支持 INNER/LEFT JOIN、GROUP BY/HAVING；窗口、UNION、CTE、子查询、视图仍有限制；结果有预算 |
| BEGIN/COMMIT/ROLLBACK、断连回滚、语句失败回滚 | 不支持保存点、锁定读、LOCK TABLES、隔离级别切换；支持独立 SET autocommit=0/1 的真实事务状态机 |
| 精确 DECIMAL、JSON 列及函数、显式列排序规则 | 仍适用现有标量兼容限制；不是完整 MySQL JSON/字符权重实现 |
| 已提交表结构元数据、SHOW REPLICATION STATUS | 普通 SHOW/信息模式行数统计不代表真实表行数；准确计数用 SELECT COUNT(*) |

常用 ALTER、后建索引、CHECK 与 RESTRICT/NO ACTION 外键已接入；单机账号/授权 SQL 使用独立用户目录，复制节点拒绝账号 SQL。详细范围见业务演进设计，不应与旧后端功能混同。
账号文件目前是各节点本地文件，**不经过 Raft**；三个新节点须使用一致的初始化账号密码。
旧模式的历史功能矩阵不适用于当前运行引擎。

## 新建表格式与性能改造

新MVCC表使用紧凑行格式 `RowEncoding=1`，新单列INT/BIGINT主键表另使用有序键
`KeyEncoding=1`。历史0格式仍按原有Gob/文本键读写，不自动迁移；因此旧表不会直接
获得新表的全部优化。投影解码可少构建无关文本，但仍读取编码行，未实现列式存储。

旧二进制不能打开新格式表，不支持直接降级。复制成员必须使用理解同一格式的版本，
没有混合版本协商或无停机滚动升级保证。迁移需保留原目录，以受支持SQL分批写入
独立新库并核对全内容；没有MVCC在线格式迁移CLI，INSERT SELECT在此后端不支持。

当前四数据库实测见[对比报告](../报告/四数据库对比报告.md)。默认256 MiB写集硬限制已取消，逻辑总量预算与内存缓冲分开控制。
临时库改为版本化二进制操作值，命名空间/键仅保存在B+树键中；空父事务可直接接管
语句写集，避免全量再复制。单机大事务不再创建持久pending副本；复制路径的pending
与Raft日志继续使用原JSON格式。每批持久记录已分配版本序号，确保取消或中途退出后
未发布版本不会被后来提交误显示；最后发布前已校验全部冲突。逐层写集缓冲约128 KiB，单机版本安装批次现为约256 KiB。

扫描时以物理读事务为边界复用固定16槽提交标记缓存；每批结束即丢弃，不能把未提交
判断缓存到后续视图。分页仍在调用消费者前释放底层读事务。聚合复用单行解码空间，
NULL及未读取字段会清空；普通SELECT结果不共享可变行缓冲。此优化不改变文件格式。

单机大事务提交会在冻结的临时库只读事务内直接读取编码写集，全部校验后按批写入；
引用仅在该只读事务存续期内使用，尾批写完才关闭，减少键和值的重复复制。
UPDATE/DELETE扫描也复用行缓冲；新旧行分开，写集编码后才允许复用，NULL字段会清空。
借用写集的方式不改变同步持久化、提交原子性或SQL兼容范围；当前批次预算见下文。性能与内存实测见当前四数据库对比报告。

键编码保持“命名空间、零字节、原始键”，校验阶段不分配编码键，构造时按精确长度一次分配。
空写集点查跳过不必要的键构造，但仍校验键边界。直接列聚合预解析列位置，JSON、NULL、
DECIMAL和排序规则仍走原值转换；复杂表达式维持通用求值。原四库报告以其程序哈希为准。

## 资源与物理内存

默认每条 SQL 文本最多 1 MiB，协议入站报文在分配前检查约 1 MiB 上限；超大报文会关闭
连接。编码后的单行/表定义最多48 KiB。单事务逻辑写集默认不设总量上限，约128 KiB
的逐层缓冲保持有界，单机版本安装批次约256 KiB，复制命令仍约64 KiB。排序默认4 MiB，
物化结果默认 16 MiB，查询临时磁盘默认 256 MiB。超限返回错误，不会回退为全表物化。
单事务临时库、语句临时库、Raft 日志和持久库仍需要额外磁盘空间；这些预算不是总磁盘上限。
`resources.transaction_write_mb` / `DB_TRANSACTION_WRITE_MB` 默认为0，表示不限制逻辑
写集总量；正数为MiB，最大1048576。预算统计每层去重后的命名空间键、2字节操作头
和原始值，不含bbolt页、map开销、保留版本及复制日志；不是进程内存或实际磁盘硬配额。
SQL失败前的语句写集会回滚；若向非空外层事务合并时遇到预算/IO错误，整笔外层事务
中止，不能提交部分合并结果。预算错误按资源错误返回1041。`query_temp_mb`仍只管查询
排序临时空间，不是MVCC写集预算。大事务实际仍受剩余磁盘、查询超时和系统能力限制。

复制仅将多数派探测限制为最多5秒，不再给整条SQL叠加隐藏的30秒超时；SQL期限由
`resources.query_timeout_ms`或请求上下文控制。Raft日志一旦提交，其应用不会因为
客户端超时而在某个副本独自停止；断连/超时后的事务结果可能未知，需按幂等键确认。

`resources.memory_limit_mb` 是 Go 运行时软目标，不能限制 mmap 和操作系统文件缓存。
Windows 可显式设置 `resources.working_set_limit_mb: 64`，启用并验证工作集硬最大值；
不成功会拒绝启动。最小 16 MiB，0 保留操作系统默认值。它限制进程驻留页，不限制全系统
文件缓存、内核内存、虚拟地址或已提交私有内存。Linux 不接受非零该选项，须使用
cgroup/容器内存额度并按真实负载验证 OOM 行为。强制限驻留会增加页故障，不能保证
物理内存、CPU 和时延同时下降。

Windows API 依据：[SetProcessWorkingSetSizeEx](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-setprocessworkingsetsizeex)。

CPU、工作集、私有内存与磁盘的统一实测口径见[四数据库对比报告](../报告/四数据库对比报告.md)。资源预算不保证所有指标同时下降。

## 单机配置

必须使用**全新、独立的数据目录**，不自动转换已有 snapshot/paged 数据。
将以下配置保存为仓库根目录的 `mvcc-local.yaml`，仅用于独立练习实例（修改示例密码）：

```yaml
server:
  host: 127.0.0.1
  port: 3310
storage:
  mode: mvcc
  path: .tmp/mvcc-local/data
resources:
  memory_limit_mb: 64
  working_set_limit_mb: 64
  max_procs: 2
  transaction_write_mb: 0
  query_timeout_ms: 120000
auth:
  username: root
  password: change-this-local-password
log:
  path: .tmp/mvcc-local/logs
```

此工作集配置仅适用于 Windows；Linux 将 `working_set_limit_mb` 设为0，并按部署环境设置容器内存额度。

```powershell
go build -o .tmp/gbaselite.exe ./cmd/gbaselite
.tmp/gbaselite.exe server --config mvcc-local.yaml
```

snapshot/paged 配置不再可用于运行；复制目录拒绝改成单机打开。旧 CLI 的
shell/import/export/backup/restore 和 binlog 写入回放明确拒绝，
防止把元数据镜像导出成空数据备份。通过在线 SQL 导入已验证的受支持语句；不应直接对
业务目录试验。replay-binlog --check-only 与 inspect-instance 仅检查旧格式迁移源。旧 SQL binlog 不能开启。

## 本地三节点与固定入口

从单机示例复制三个配置，分别改成不同的 SQL 端口与数据目录：

| node_id | server.port | storage.path | replication.bind | bootstrap |
| --- | ---: | --- | --- | --- |
| n1 | 3311 | .tmp/mvcc-n1 | 127.0.0.1:7311 | true |
| n2 | 3312 | .tmp/mvcc-n2 | 127.0.0.1:7312 | false |
| n3 | 3313 | .tmp/mvcc-n3 | 127.0.0.1:7313 | false |

每份增加（node_id、bind、bootstrap 按表修改）：

```yaml
replication:
  enabled: true
  node_id: n1
  bind: 127.0.0.1:7311
  bootstrap: true
  peers: n1=127.0.0.1:7311,n2=127.0.0.1:7312,n3=127.0.0.1:7313
```

只有第一次、且目录无 Raft 状态的 n1 引导集群；重启保留原数据和身份配置。不得删除
Raft 日志来“强制选主”，不得把已有数据的单机目录直接开启复制。启动三个 server 后：

```powershell
.tmp/gbaselite.exe proxy --config n1.yaml --listen 127.0.0.1:3307 --peers n1=127.0.0.1:3311,n2=127.0.0.1:3312,n3=127.0.0.1:3313
```

客户端连接代理端口 3307。直接连接任一节点执行 `SHOW REPLICATION STATUS` 可以看到
本节点状态、主节点 ID、主节点 Raft 地址和应用日志序号；这里的 Raft 端口不是 SQL 端口。
代理每 500 ms 开始下一轮检测，失败探测有 750 ms 超时，实际切换时间还包括选举、网络
和客户端重连。默认代理最多 64 条业务连接，`--max-connections` 可调整。PING/端口连通
不代表有写入多数派；可用性检查必须执行 SQL，如 SELECT 1。

跨机器的 Raft 通信必须配置 `replication.tls_cert/tls_key/tls_ca`，使用包含正确 IP/DNS
SAN、支持 serverAuth/clientAuth 的证书，且三节点信任同一个专用 CA。无证书仅允许
字面量回环 IP。代理跨机器探测 SQL 时需要 `--tls-ca sql-ca.pem`，并启用节点 SQL TLS；
SQL TLS 和 Raft TLS 是两套配置。代理转发客户端 TLS，不终止 TLS，节点 SQL 证书需包含
客户端实际连接的代理域名。证书自动轮换不在当前实现范围内。

三节点都运行在同一台机器只能验证流程，不能抵御整机故障。实际容错须放在独立故障域。
单个代理仍是入口单点；需要入口容错时，在应用主机各运行代理或配置多个代理地址/外部
负载均衡。没有内置 VIP、DNS 切换或动态扩缩容。

## 持久性与未完成事项

提交确认依赖多数派日志持久化和本节点应用成功。客户端遇到断连或超时，提交结果可能
未知，应查询业务幂等键后决定重试；代理不会冒险自动重放。三节点最多容忍一个节点
失联，多数派同时不可用时停止服务，不能保证磁盘丢失或多个故障域同时损坏后不丢数据。
复制不等于备份：目前没有受支持的在线备份/恢复 CLI；停服后保留各节点完整目录，并
在隔离副本上演练同身份恢复，不能只备份 mvcc.db 或只备份 Raft 日志。

大事务安装未发布版本时同时持久保留分配序号，重启及快照恢复取已应用/已分配序号的
最大值，防止新提交意外发布崩溃事务的部分版本。单机提交在发布标记前检查取消，
取消不会把正常存储标为IO故障；复制状态机仍按确定性日志完成应用。

复制路径提交后的 pending 写集按批删除，中止时尽力复制 abort；崩溃遗留的本地事务临时文件在
独占打开数据库后清理。失去多数派时未清完的 pending、未发布版本和删除表的旧数据
可能留在磁盘。单机包 API `CompactHistory` 可在保留活跃快照的前提下回收旧版本供页复用；
尚无自动集群版本 GC、磁盘收缩、完整孤儿清理、在线成员替换和在线物理备份。

自动化测试覆盖不同事务不同行提交、同行冲突、唯一键/DDL 冲突、语句回滚、重启、快照
恢复、三节点选举与旧节点追赶、少数派拒绝、跨任期提交拒绝、复制 mTLS 双向认证、超限报文分配前拒绝、MySQL 预处理事务、代理
主节点故障后重连写入。未覆盖长期分区、断电/文件系统故障注入、跨机时钟/网络扰动、
Windows race 检测和长期混合负载，不能据此称为经过生产认证的海量数据库。

## 本地有界维护与并发提交

单机小事务在没有其他提交时立即执行；提交期间到达的请求可共享下一次磁盘同步。
排队最多32个请求、512 KiB逻辑预算，每组最多256 KiB；队列满时走串行提交。
每笔事务单独校验冲突，组内前序写入也会被后序请求检查。复制路径不使用此队列。

单机历史清理在有界批次之间释放锁，保留最老活跃快照所需版本；行内清理会续扫，
不会因单行历史过多反复从表头开始。释放页供后续写入复用，不自动缩小物理文件。
恢复快照会使在途清理退出；集群版本回收仍需统一保留边界。

简单过滤在查询内绑定列位置，点查跳过扫描计划；复杂表达式仍使用原求值器。
平铺版本键仅有隔离测试原型，没有生产迁移命令。普通覆盖索引、完整批量执行器、
顺序 WAL 与可恢复检查点仍未完成。已有四库报告只证明其中记录的程序哈希。

## 共用计划与 EXPLAIN

`EXPLAIN SELECT` 已接入 MVCC 实际访问计划，支持 MySQL 风格12列结果和预处理协议。点查 rows=1 是上界，扫描统计未知时返回NULL；不会执行表达式或扫描全表获取统计。支持 INNER/LEFT JOIN 及分组解释，ANALYZE、FORMAT=JSON 未实现。完整演进方案与 Java 兼容门槛见[业务数据库演进设计](MVCC业务数据库演进设计.md)。恢复输入无效时不再提前使健康事务失效；真正替换数据库仍使旧事务失效。

单机新增 `BACKUP MVCC TO` / `RESTORE MVCC FROM`、`GC MVCC` 和 `COMPACT MVCC TO` SQL 管理扩展；不能用于本页 Raft 集群备份恢复。操作限制见[Java 与 MVCC 使用验证](Java业务兼容验证.md)及[演进设计](MVCC业务数据库演进设计.md)。
