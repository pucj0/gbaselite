# 查询资源控制与索引 JOIN

本轮增加可配置的执行期限、外部排序、DISTINCT 落盘去重、结果/中间状态预算，以及选择性索引 JOIN。它们减少部分查询的瞬时分配，不能把 Go 的软内存限制变成物理内存硬上限，也不能替代分页存储。

## 配置

```yaml
resources:
  query_timeout_ms: 30000
  sort_memory_mb: 8
  query_result_memory_mb: 32
  query_temp_mb: 512
  query_temp_path: ""
```

这些选项默认均为 `0` 或空字符串，保持旧版本默认行为；示例数值是可自行调整的运行预算。`query_timeout_ms` 最大为 86400000；内存和临时磁盘选项单位为 MiB，最大为 1048576。`query_temp_path` 为空时使用操作系统临时目录；非空目录必须已存在并可写。

| 配置 | 环境变量 | 作用 |
| --- | --- | --- |
| `resources.query_timeout_ms` | `DB_QUERY_TIMEOUT_MS` | SQL 执行期限；0 不设置服务器执行期限 |
| `resources.sort_memory_mb` | `DB_SORT_MEMORY_MB` | 启用有预算的 ORDER BY 和 DISTINCT；0 保留原路径 |
| `resources.query_result_memory_mb` | `DB_QUERY_RESULT_MEMORY_MB` | 已接入的物化结果和中间状态预算；0 不设此预算 |
| `resources.query_temp_mb` | `DB_QUERY_TEMP_MB` | 单次查询外部排序临时文件的总字节预算；0 不设此预算 |
| `resources.query_temp_path` | `DB_QUERY_TEMP_PATH` | 外部排序临时目录 |

嵌入式调用可以设置 `Engine.QueryOptions` 和 `Session.Context`。引擎配置应在开始并发服务前完成。同一 Session 仍不能并发执行多个请求。

## 排序与 DISTINCT

普通和表达式 ORDER BY 可把批次写入私有临时文件，再执行多路归并；合并同时最多打开 8 个输入文件。每行保存递增序号，排序键相等时保持源行顺序，保留原有 OFFSET/LIMIT 行为。最终行通过已有协议流式接口逐行输出；非流式调用仍需要物化选中的结果并遵守结果预算。

临时编码保留 NULL、整数、无符号整数、浮点数、布尔值、日期、字节、JSON 文档标记、精确 DECIMAL 和显式文本排序规则。它不是持久化文件格式，不用于跨版本恢复。

DISTINCT 使用两次有预算的排序：先按已有去重键聚合并保留首次出现的行，再恢复源顺序。两个排序器平分排序预算并共享临时磁盘总量。内部 API 至少需要 128 KiB 总排序预算；YAML 以 MiB 配置。两个阶段的源数据、归并输入和输出可能同时存在，临时文件预算应留出余量。

预算包含保留的行头和变长值的估计值，不等同于 RSS。为了保证多路归并不会同时加载超宽行，每个排序器拒绝估计大小超过自身预算 1/16 的单行；DISTINCT 平分预算后再应用此规则。此时应增加排序预算或减少投影字段，不会静默超过预算。

SQL 超时、取消、磁盘预算耗尽、文件 I/O 错误和协议写入失败均通过同一路径关闭文件并删除当前排序器创建的文件，不会递归删除临时目录。直接终止进程后可能留下带 `gbaselite-sort-` 前缀的文件；系统没有自动清理任意历史文件的后台任务。

## 取消与仍需区分的边界

事务锁等待使用带取消检查的 TryLock 重试，超时后不会留下继续抢锁的后台 goroutine。已接入的扫描会在每个源行检查期限，包括 WHERE 不匹配任何行的情况；排序、归并、临时写入、索引 JOIN 和输出也检查期限。

这属于协作式取消，不会强行中断正在进行的一次磁盘系统调用，也不是 MySQL `KILL QUERY`。写入一旦进入需要完成的持久化阶段，不能仅因期限经过就把已提交事务报告成回滚。客户端网络断开不等于服务端必然立即收到取消信号；流式网络写入错误会终止后续输出并触发清理。

GROUP BY、窗口、递归查询和 JOIN 的部分中间状态仍采用物化实现；已接入内存账户的路径在保留新状态前检查预算，超限返回资源错误。不能把“支持外部排序”理解为所有聚合都支持落盘。源表数据、页缓存、其他连接、解析缓存和 Go 运行时内存均不包含在单个排序器的预算中。

## 选择性索引 JOIN

对于右表连接键具有单列 PRIMARY/UNIQUE 索引的纯等值 INNER/LEFT JOIN，可直接探测右表索引，避免为右表复制整份数据再构建哈希表。保留左表顺序、重复的左行以及 LEFT JOIN 未匹配行的 NULL 扩展，并重新判断 ON 表达式。

当前入口支持兼容的 INT/BIGINT、BOOLEAN，以及使用二进制比较的文本键。复合键、普通非唯一索引、RIGHT JOIN、带额外条件的 ON、大小写不敏感文本键、浮点和 DECIMAL 键仍使用一般连接路径。接近或超过整数 2^53 边界的特殊探测值采用逐行核对，以保留现有数值比较行为。

此路径仍物化连接结果，并不保证任意多对多 JOIN 都能在固定内存中完成。连接结果遵守已配置的物化预算。

局部基准：Windows amd64 / i5-12600KF，5 条左行对 10000 条右行，其中 3 条匹配、2 条未匹配；每组 10 次、重复 3 组，中位值如下。基准比较原右表资格化复制加一般连接与新索引探测，未包括网络或持久化，不代表所有 SQL 的提升。

| 路径 | 每次耗时 | 分配字节 | 分配次数 |
| --- | ---: | ---: | ---: |
| 一般连接 | 3.040 ms | 5,571,529 | 30,094 |
| 索引连接 | 6.660 µs | 8,504 | 39 |

验证包括跨 64 个排序运行段的归并、相同键稳定顺序、隐藏排序列与分页、JSON/DECIMAL/排序规则往返、损坏长度拒绝、总临时文件预算、取消和错误清理，以及索引连接与一般连接的结果对照。全库回归结果以本轮整体验证为准。
