# WAL、普通覆盖索引、批次执行与布局迁移

本页描述当前代码能力，不替代四数据库实测报告，不承诺所有指标优于 SQLite。

| 能力 | 已接入 | 边界与成本 |
| --- | --- | --- |
| 顺序 WAL | 单机 SQL 事务分帧 CRC、整组 SHA-256、同步封口、重放 | 默认关闭，保留 bbolt 同步，额外磁盘写入；没有日志归档/PITR；不是 Raft WAL |
| 普通覆盖索引 | 新表普通/联合索引左前缀等值查找，索引列与主键覆盖 | 旧表不自动回填，可经 DDL 重建；无成本统计；更多写入、磁盘和 GC 工作 |
| 批次执行 | 单表扫描到过滤、投影、聚合、排序输入的有界批次消费 | 128 行/64 KiB 逻辑预算；安全整数支持原生批次内核，其余回退；JOIN/GROUP BY 由独立算子支持 |
| 布局迁移 | 嵌套和平铺版本格式双向流式转换 | 单机停机维护；保留所有历史，不能代替历史 GC；无自动切换或 Raft 滚动迁移 |

## WAL 开关与恢复

```yaml
storage:
  mode: mvcc
  local_wal: true
```

WAL 位于 `versioned/local.commit.wal`。提交组先写临时日志，同步封口后原子发布，再用有界物理事务安装数据并同步提交标记。重启完整校验日志后幂等重放，成功后清空；选项关闭也会恢复遗留日志。发布后的 I/O 错误属于提交结果不确定，实例停止接受后续写入，需要修复故障并重启恢复，不能据报错假定回滚。不要删除现场 WAL。发布前取消不提交；发布后继续完成持久化。

当前仍同步数据页，先保证持久性和恢复边界，不能因 WAL 已加入而开启 NoSync。测试覆盖重放、损坏封口拒绝、冲突与取消，不等于硬件掉电认证。

## 普通覆盖索引

```sql
CREATE TABLE orders(id BIGINT PRIMARY KEY, user_id BIGINT, state INT,
  note VARCHAR(200), KEY user_state(user_id,state));
EXPLAIN SELECT id,state FROM orders WHERE user_id=10;
```

新建表记录 `SecondaryEncoding=1`。索引记录以索引列编码加行主键区分重复项，值保存主键与覆盖列；行和索引共享事务版本，更新、删除和回滚一致。覆盖全部 SELECT/WHERE/ORDER BY 所需列时 EXPLAIN 显示 `Using index`，否则回表。INT/BIGINT 受既有安全比较范围限制；文本仅在二进制比较等价时选择，JSON 等类型回退扫描。索引键和覆盖值仍受已有键值长度限制，超宽索引写入返回错误，语句不会部分提交。

旧表格式 0 保持扫描，需要另行计划重建/回填；布局迁移不会改变逻辑索引格式。CREATE INDEX 已支持影子重建与并发写冲突检测，失败原子回滚；仍无任意二级范围排序优化、统计成本选择和旧版本混合写入支持。

## 单机离线迁移步骤

1. 停止业务写入及数据库服务，保存原配置和完整实例备份，记录原程序版本。不要在运行中复制裸数据库文件。
2. 在有足够空闲空间的位置选择不存在的目标目录，父目录预先准备好。源参数是含 `mvcc.db` 的 `versioned` 目录，命令会获取数据库独占文件锁，检测常规目录中的 Raft 状态并拒绝迁移。
3. 执行 `gbaselite migrate-layout --source E:\instance\data\versioned --target E:\candidate\versioned --layout flat`。此示例只说明参数，不会自动在正式目录运行。
4. 命令按最多约 256 KiB 逻辑记录预算同步写入，复制所有历史版本、提交标记、计数器和目录元数据。源/目标按规范顺序计算 SHA-256，只有匹配才发布 `mvcc.db` 并将未完成标记改为 `migration.txt`。目标文件占用可能大于源文件，尤其历史未回收时。
5. 保留原实例。目标只含 MVCC 数据，不含用户、配置和日志；在隔离实例根目录下准备相同用户文件与配置，把目标目录放在该根的 `versioned` 位置，使用本版本程序验证业务查询、行数、约束、事务、重启、备份和监控，再安排停机切换。禁止旧程序打开平铺数据库。
6. 切换前失败时使用原实例恢复服务。切换后若已发生新写入，不能直接退回旧副本，否则丢失新数据；须停机把新库导出到另一个新目录并验证后回切。`--layout nested` 只转换物理布局，不撤销新逻辑索引格式，因此不是任意旧二进制的降级工具。

取消或磁盘错误可能留下带 `migration.incomplete` 的目标，系统拒绝打开。保留源，排查后选择另一个新目标重试；不会自动删除失败目录。该机制面向离线转换，不提供集群滚动切换、在线迁移、断点续传或完整备份编排。

## 验证与性能解释

使用隔离临时数据库验证历史版本、零字节行键、删除、双向迁移、迁移后 WAL 写入、GC 保留活动快照、重启以及已存在目标拒绝覆盖。单表批次测试检查边界、取消、聚合及倒序 LIMIT；普通索引与强制扫描做结果差分。

64 KiB/256 KiB 是应用逻辑批次目标，不包含全部 Go 对象、bbolt 映射页、结果和操作系统缓存，不是物理内存保证。没有新生产规模对比测量之前，不给出 CPU、RSS 或延迟提升百分比。
